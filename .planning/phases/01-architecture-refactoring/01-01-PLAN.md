    Modify `apps/site/server/services/settings.service.ts` per decisions D-16, D-17, D-18:

    **Change 1 — Add import at top (after existing imports):**
    ```typescript
    import { settingSchemas } from './settings.schema'
    import { z } from 'zod'
    ```

    **Change 2 — Modify `upsert()` to validate with Zod before write:**
    Before the `db.insert(...)` call, resolve the Zod schema for the key:
    ```typescript
    const schema = settingSchemas[key] ?? z.unknown()
    const parsed = schema.parse(value)
    ```
    Then use `parsed` instead of `value` in both the `insert.values()` and `onConflictDoUpdate.set()` calls. Replace both `value: value as any` with `value: parsed` (no `as any` needed — Drizzle accepts the Zod-parsed type).

    If `schema.parse(value)` throws ZodError, let it propagate — the API route's try/catch will handle returning a 400 error. Do NOT wrap in try/catch inside the service.

    **Change 3 — Modify `batchUpdate()` to use `db.transaction()`:**
    Replace the for-loop calling `SettingsService.upsert()` with:
    ```typescript
    return await db.transaction(async (tx) => {
      const results = []
      for (const item of items) {
        const schema = settingSchemas[item.key] ?? z.unknown()
        const parsed = schema.parse(item.value)
        const record = await tx
          .insert(systemSettings)
          .values({
            key: item.key,
            value: parsed,
            category: item.category,
            description: item.description,
            updatedAt: new Date(),
          })
          .onConflictDoUpdate({
            target: systemSettings.key,
            set: {
              value: parsed,
              updatedAt: new Date(),
              ...(item.category !== undefined ? { category: item.category } : {}),
              ...(item.description !== undefined ? { description: item.description } : {}),
            },
          })
          .returning()
        results.push(record[0])
      }
      return results
    })
    ```
    The transaction callback uses `tx` (not `db`) for all operations. If any `schema.parse()` throws, the transaction auto-rolls back (no manual catch needed).

    **Change 4 — Add a static `parseValue()` helper (optional convenience method):**
    ```typescript
    static parseValue(key: string, value: unknown): unknown {
      const schema = settingSchemas[key] ?? z.unknown()
      return schema.parse(value)
    }
    ```

    Do NOT change `getAll()` or `getByKey()` — they remain unchanged. Do NOT add error wrapping inside the service methods — let Zod errors propagate naturally.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
