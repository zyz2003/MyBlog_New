    Create the NEW file `apps/site/server/api/themes/active.css.get.ts` with the following implementation:

    ```typescript
    import { themeManager } from '../../core/theme'

    /**
     * GET /api/themes/active.css
     * Public endpoint — returns active theme CSS variables as text/css (per D-08)
     *
     * Uses themeManager.getActiveCSS() which generates :root { ... } CSS from
     * the active theme's config, calling CSSVariablesMap(config) internally.
     *
     * Returns text/css; charset=utf-8 for direct <link rel="stylesheet"> injection (per D-09)
     * Caching: no Cache-Control header set — browser uses default heuristics.
     *           Theme changes (via admin save) require a page refresh or
     *           cache-busting query param (out of scope for this phase).
     */
    export default defineEventHandler((event) => {
      const css = themeManager.getActiveCSS()

      if (!css) {
        // No active theme — return empty CSS (200, not 404)
        // Frontend gracefully handles empty stylesheet
        setHeader(event, 'Content-Type', 'text/css; charset=utf-8')
        return '/* No active theme */'
      }

      setHeader(event, 'Content-Type', 'text/css; charset=utf-8')
      return css
    })
    ```

    Key design decisions:
    - File named `active.css.get.ts` — Nitro parses the `.css` as part of the route, making the endpoint accessible at `/api/themes/active.css`
    - Returns empty CSS comment when no active theme (200 response, not 404) — prevents browser console errors from <link> load failures
    - Uses `setHeader(event, 'Content-Type', 'text/css; charset=utf-8')` — sets correct MIME type
    - Does NOT set Cache-Control — browser uses default caching; cache strategy is deferred per Claude's Discretion
    - No auth check — this is a public endpoint (theme CSS is public data)
